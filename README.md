# LLM 학습 자료 분석의 대기 시간 개선

학습 자료를 업로드하면 AI가 내용을 분석해 학습 주제를 만듭니다. 기존 흐름에서는 **전체 분석이 끝날 때까지 학습을 시작할 수 없었고**, 분석 중 연결이 끊기면 자료를 다시 업로드해야 했습니다.

이 프로젝트는 두 가지를 개선했습니다. 완성된 주제부터 학습할 수 있도록 첫 대기 시간을 줄이고, 분석 작업을 서버에 저장해 새로고침과 재접속 후에도 이어서 확인할 수 있게 했습니다.

## 핵심 결과

- 실자료 비교 실험에서 **첫 학습 대기 시간을 약 50% 단축**했습니다.
- 페이지를 새로고침하거나 다시 접속해도 기존 분석 작업의 상태와 결과를 확인할 수 있게 했습니다.
- 서버가 재시작해도 저장된 입력과 작업 상태를 바탕으로 분석을 복구할 수 있게 했습니다.

## 1. 전체 분석을 기다리지 않고 학습 시작하기

처음에는 LLM 응답을 SSE로 받아 완성된 학습 주제부터 제공하는 방식을 생각했습니다. 하지만 응답이 중간에 실패하면 재시도한 LLM이 이전과 다른 주제 구성으로 답할 수 있습니다. 이미 보여준 내용과 새 응답을 단순히 합치면 학습 내용이 중복되거나 빠질 수 있습니다.

이를 해결하기 위해 **학습 계획을 먼저 고정**했습니다.

1. 원문을 학습 단위로 나누고, 각 주제가 담당할 범위를 계획합니다.
2. 계획의 주제 ID, 순서, 원문 범위를 검증하고 저장합니다.
3. SSE 응답에서 주제 하나가 완성되면 해당 범위와 결과를 검증·저장한 뒤 제공합니다.
4. 호출이 실패하면 저장된 계획을 유지한 채 **완료되지 않은 주제만** 다시 생성합니다.

재시도의 기준이 새 LLM 응답이 아니라 저장된 계획이므로, 이미 완료한 주제를 보존하면서 남은 범위를 처리할 수 있습니다.

## 2. 연결이 끊겨도 남는 분석 작업

분석 요청을 받은 HTTP 연결에서 LLM 호출이 끝날 때까지 기다리는 대신, 요청 접수와 실제 분석 실행을 분리했습니다.

```text
자료 업로드
   → 입력 저장·작업 생성
   → 작업 ID 반환
   → 별도 실행기가 LLM 분석
   → 상태와 결과 저장
   → 클라이언트가 작업 ID로 조회
```

작업 상태와 입력을 서버 메모리나 브라우저 화면에만 두지 않고 저장소에 기록합니다. 따라서 브라우저 연결이 끊겨도 분석 작업은 유지되며, 사용자는 같은 작업 ID로 진행 상태나 완료 결과를 다시 확인할 수 있습니다.

실행 중 서버가 재시작한 경우에도 저장된 작업과 입력을 읽어 복구합니다. 완료 결과를 기록할 때는 현재 작업 실행자만 상태를 변경할 수 있도록 해, 이전 실행의 늦은 응답이 복구된 작업의 결과를 덮어쓰지 않게 했습니다.

## 측정 기준

성과의 기준은 **전체 분석 완료 시간**이 아니라, 사용자가 **첫 번째 학습 주제를 시작할 수 있을 때까지의 시간**입니다. 실자료를 사용해 전체 완료 후 학습을 시작하는 흐름과 주제별로 제공하는 흐름을 비교했습니다. 전체 생성 시간과 첫 학습 대기 시간은 서로 다른 지표로 기록했습니다.
